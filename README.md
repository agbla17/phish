# 🛡️ PhishGuard 

PhishGuard is a machine learning-based web application designed to detect and prevent phishing attacks. It analyzes URLs and email-related features to determine whether a link is legitimate or malicious.

---

## 🚀 Features

* 🔍 Detects phishing URLs using ML models
* 📊 Feature extraction from URLs and email data
* 🌐 Simple frontend interface for testing links
* ⚡ Fast predictions using trained model
* 🧠 Train your own model using provided scripts

## ⚙️ How It Works

1. User enters a URL
2. Backend extracts features
3. Machine learning model analyzes patterns
4. Returns prediction: **Phishing or Safe**

## 🧪 Setup & Installation

### 1. Install dependencies

```
pip install -r ml/requirements.txt
```

---

### 2. Train the models

```
python ml/train.py
```

This will generate the trained model files required for predictions.

To train BERT, RoBERTa, CNN, or LSTM email classifiers on the full CEAS_08
dataset, first install the neural-training dependencies from
`ml/requirements.txt`, then run:

```text
python ml/train_neural_models.py
```

This training-only script does not create a test split or calculate evaluation
metrics. It saves model checkpoints under `ml/artifacts/neural_models/`. BERT
and RoBERTa download pretrained weights and tokenizers on first use; CNN and
LSTM train their vocabulary and embeddings on CEAS_08. Use `--models bert
roberta`, `--epochs 1`, or `--max-rows 5000` for a smaller run. The supplied
model-comparison F1 figures are separate and are not generated by this script.

To evaluate the existing email model without retraining it:

```
python ml/validate_email.py
```

The validation metrics are also saved to
`ml/artifacts/email_validation_results.json`.

To classify every email in `dataset/CEAS_08.csv` without modifying the source
file:

```
python ml/predict_ceas.py
```

Predictions are saved to `ml/artifacts/CEAS_08_predictions.csv`.

The email model uses shared indicator features for urgency, threats (including
deletion/suspension), account and credential verification, calls to action,
keywords, casing/punctuation, URL/domain structure, sender identity, and
authentication headers, with authentication results read only from the
message-header block. Email metrics use grouped out-of-fold
`StratifiedGroupKFold` predictions (scalers fit within each training fold).
URL metrics group all variants from one hostname into the same fold to reduce
host-level leakage. `ml/artifacts/metrics.json` contains these OOF results;
`python ml/evaluate_all_datasets.py` publishes them without evaluating the
final models on their training rows. PhishTank contains only positive examples
and can report recall/misses, not specificity or false-positive rates.

The attachment classifier is currently trained and evaluated on synthetic
feature vectors, not a labeled corpus of real files. Its cross-validation
metrics are useful for pipeline checks only and are not a real-world accuracy
claim. Static attachment checks remain useful as indicators, not a replacement
for antivirus or sandboxing.

---

### 3. Run the backend server

```
node server.js
```

The server starts the local Python inference service and serves the frontend at
`http://127.0.0.1:3000`. Open the app through this URL rather than loading the
HTML file directly.

By default, the Node API binds only to loopback and permits the matching
localhost origins. Configure `PORT`, `HOST`, and `CORS_ORIGINS` in the process
environment when changing the local endpoint. Do not expose the unauthenticated
development API directly to the internet; place it behind an authenticated
deployment gateway before making it remotely accessible.

## 📊 Dataset

Training uses the checked-in `dataset/CEAS_08.csv`, `dataset/urldata.csv`,
and `dataset/dataset_phishtank.csv` files. Running `python ml/train.py`
regenerates the models and evaluation metrics under `ml/artifacts/`.
